# Next-Visit Theo Model Evaluation

An interactive rebuild of a model-evaluation dashboard I built during a summer 2025 analytics internship at a Las Vegas integrated resort. It shows how a model that predicts each loyalty guest's theoretical gaming win ("theo") for their next trip performs, broken down by loyalty tier, game type, booking lead time, predicted-worth band and month.

**Live demo:** `https://patrick-liu81.github.io/next-visit-model-eval/`

> **About the data.** The original data is confidential, so every number in this repository is synthetic, generated by `scripts/generate_synthetic_data.py`. There is no guest data, no internal table names and no real results.
>
> **What is real:** the SQL logic and metric definitions (`sql/evaluation_queries.sql`) follow the Databricks queries I wrote during the internship, with table and column names generalized. The booking-window query is a cleaned-up version of my original. The dashboard layout mirrors the one I built. Tier names are the public loyalty-program tiers (Chairman, Black, Platinum, Red).
>
> **AI use:** I used AI tools (Claude) to help build this public version: generating the synthetic data, writing the HTML dashboard and editing the write-up.

## What's in the dashboard

| Tab | What it shows |
|---|---|
| **Dashboard** | KPI tiles, normalized MAE and bias by any breakdown, a calibration chart and a table view. Every filter recomputes the metrics live from trip-level rows. |
| **Why the metric definition matters** | The main lesson of the project: averaging per-trip percentage errors produces huge, misleading numbers when some trips have near-zero actual theo. Group-level (dollar-weighted) metrics fix it. |
| **Case study write-up** | Context, what I built, findings, and what I would do differently. |
| **SQL** | Sanitized versions of the evaluation queries. |

## Metrics

| Metric | Definition | Why |
|---|---|---|
| Normalized MAE | `mean(|actual − predicted|) / mean(actual)` | Dollar-weighted error, comparable across segments of very different size |
| Aggregate bias | `(mean(actual) − mean(predicted)) / mean(actual)` | Negative means the model over-predicts the segment |
| Median abs. % error | `median(|actual − predicted| / actual)` | Typical single-trip miss |
| Avg individual % error | `mean((actual − predicted) / actual)` | The original metric, kept only to show how it breaks |

## Repository layout

```
index.html                         dashboard (plain HTML/JS/SVG, no build step, no dependencies)
data/synthetic_trips.csv           8,000 synthetic trips
scripts/generate_synthetic_data.py regenerates the CSV (NumPy)
sql/evaluation_queries.sql         sanitized evaluation queries
docs/WRITEUP.md                    case study
```

## Run it locally

```bash
python scripts/generate_synthetic_data.py   # optional: regenerate data (pip install numpy)
python -m http.server 8000                  # then open http://localhost:8000
```

Opening `index.html` directly as a file won't load the CSV (browsers block `fetch` on `file://`); use the local server or GitHub Pages.

## Original stack vs. this rebuild

- **Original:** Databricks SQL and dashboards on Azure, Snowflake, Tableau.
- **This rebuild:** Python for synthetic data, a single static HTML page for the dashboard, hosted on GitHub Pages.
